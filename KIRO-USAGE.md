## Session 2 — continuation (this session)

### Written by hand (agent, no Kiro)

Live testing found three real bugs in `server.js`, fixed by hand:

1. **Wrong RPC nodes** — the server used `bsc-dataseed` + `bsc.publicnode.com`.
   Publicnode rate-limits aggressively and its rate-limit errors were
   misclassified as mint reverts. Swapped to `bsc-mainnet.public.blastapi.io`
   (primary) + `bsc-dataseed.bnbchain.org`.
2. **Rate-limit misclassification** — RPC error `-32005` / "Rate limit exceeded"
   is now reported as `unavailable`, never as a revert.
3. **False red-flag on gated mints** — a verified contract whose mint reverts
   (free lane gated, sold out, or now paid) was labelled a honeypot. It is now
   `ambiguous` with an explanation; `red-flag` is kept for unverified sources
   and no-code addresses.
4. **Sim gas too low** — the mint sim used a 300k gas cap, but real mints cost
   more (EMBERANVIL's mint used 453,324 gas). Raised to 1,000,000.
5. **Missing selector** — `mintFree()` (`0x8ab53447`, verified via keccak) was
   not tried, so Star Agent's free mint was missed. Added as a fourth selector.

The matching verdict/gas/selector notes in
`.kiro/specs/triage-app/requirements.md` and `design.md` were updated by hand
to match. All live tests in this session were run by hand against the local
server.

### Generated by Kiro (this session)

One non-interactive call:

```bash
kiro-cli chat --no-interactive --trust-all-tools "<prompt asking for the frontend + docs>"
```

Kiro generated, unedited afterwards except for this file:

- `public/index.html` — single self-contained page (inline CSS + JS)
- `README.md`
- `LICENSE` (MIT)
- `.gitignore` (ignores `node_modules`, explicitly does NOT ignore `.kiro/`)

Kiro's own summary claimed "18/18 checks pass" for those files; the agent
verified independently that `GET /` returns 200 and the page contains the
required form, verdict block, evidence sections, and disclaimer.

## What Kiro did not do

- No deployment, no GitHub repo creation (later steps, not done here).
- No transactions, no wallet connection, no signing — the app is read-only
  by design, and nothing in either session sent a transaction.
